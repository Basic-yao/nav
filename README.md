# Nav · 个人导航页

一个轻量、零依赖、纯静态的个人导航站。前台 `index.html` 负责展示，后台
`admin.html` 负责维护数据；分类与链接以 `nav.json` 为权威数据源，`data.js`
用于离线回退。

## 项目简介

本项目由静态 HTML、CSS 与原生 JavaScript 组成，无需构建、无需依赖安装、
无需后端即可展示。页面采用左侧分类栏、右侧卡片网格和顶部搜索栏；后台提供
分组/链接的增删改、拖拽排序、图标自动获取与数据导出。

仓库文件可在任意静态托管服务（如 GitHub Pages）上发布，也可以在本机启动
HTTP 服务后访问。

## 核心特性

- 纯前端、零依赖，无构建步骤
- 前台只读展示，后台完整可视化编辑
- `nav.json` 优先加载，无数据服务时回退 `data.js`
- 分类与卡片支持拖拽排序
- 站内搜索匹配标题、链接与描述；可切换 Bing、百度、Google
- 浅色/深色主题跟随系统，也可在当前会话手动切换
- 响应式布局，窄屏自动使用固定图标侧栏
- 支持显式图标地址或自动获取 favicon

## 完整目录结构

```text
nav/
├── index.html        # 前台展示页
├── admin.html        # 后台管理页
├── app.js            # 前台主逻辑；后台运行时也参与渲染、搜索与编辑
├── custom.js         # 后台增强逻辑：图标抓取、自动补全、导入导出等
├── data.js           # 内置兜底数据；加载后提供 navData 与 __NAV_ORIGINAL__
├── nav.json          # 当前权威导航数据
├── styles.css        # index.html、admin.html 共用样式
├── logo.png          # 项目图标
├── .gitattributes    # Git 文本属性
└── README.md
```

### 各文件用途

| 文件          | 前台 index.html         | 后台 admin.html         | 用途 |
|---------------|------------------------|-------------------------|------|
| index.html    | 使用                   | 不使用                  | 纯展示入口，仅引用 data.js、app.js |
| admin.html    | 不使用                 | 使用                    | 管理入口，仅引用 data.js、custom.js |
| app.js        | 使用                   | 运行时进入同一逻辑      | 数据加载、渲染、搜索、主题、编辑与拖拽 |
| custom.js     | 不使用                 | 使用                    | 后台增强交互、图标获取、导入导出 |
| data.js       | 使用                   | 使用                    | 定义 navData 与 __NAV_ORIGINAL__ 兜底数据 |
| nav.json      | 优先加载               | 优先加载                | 权威数据，需经 HTTP(S) 获取 |
| styles.css    | 使用                   | 使用                    | 布局、组件、响应式与深浅色主题 |
| logo.png      | 资源                   | 资源                    | 项目图标 |

> `app.js` 与 `custom.js` 均包含部分渲染、编辑和拖拽逻辑。新增功能时建议先核对
> 两处实现，避免前台与后台行为不一致。

## 前台与后台的分工

### 前台 index.html

- 不显示"添加分组""编辑/删除""导出 nav.json"等控件
- 点击分类后显示该分类
- 链接卡片在新标签页打开目标地址
- 使用站内搜索、外部搜索引擎和主题切换
- 仅在 `nav.json` 加载失败时回退 data.js

### 后台 admin.html

- 卡片可拖拽排序，分类也可在侧栏拖拽排序
- 支持添加、编辑、删除分类和链接
- 可从分组选择、自动补充或抓取图标
- 支持重置为内置数据
- 可导出当前数据为 `nav.json`
- 页面通过 URL 文件名判断模式：

```js
const EDIT_MODE = /admin\.html$/i.test(window.location.pathname);
```

因此必须通过 `http://localhost/.../admin.html` 或部署后的同源地址打开，
不能依赖文件路径在文件系统中的位置。

## 本地预览

### 方式一：启动本地 HTTP 服务（推荐）

仓库根目录执行：

```bash
python3 -m http.server 8080
```

然后访问：

- 前台：http://127.0.0.1:8080/index.html
- 后台：http://127.0.0.1:8080/admin.html

本地 HTTP 服务可以正常加载 `nav.json`，并验证 URL 文件名判定、外部
搜索引擎、图标抓取与主题跟随。

### 方式二：直接双击 HTML（仅离线回退）

双击 `index.html` 会以 `file://` 打开。此时浏览器通常无法执行相对路径
的 `fetch('nav.json')`，页面会回退到 `data.js` 的内置数据。

这种方式适合快速检查页面结构和样式，但不能验证 `nav.json` 内容，也不适合
完整测试后台。

## 数据管理

### 数据优先级

1. `nav.json`：部署后由 HTTP(S) 请求加载，是当前权威数据源
2. `data.js`：仅在 `nav.json` 不可达、响应异常、解析失败或为空时回退
3. localStorage：保存本机编辑草稿，不替代仓库中的 `nav.json`

### 通过后台修改数据

1. 启动本地 HTTP 服务并打开 `admin.html`
2. 添加或编辑分类、链接、图标
3. 使用拖拽调整分类与卡片顺序
4. 点击"导出 nav.json"
5. 将下载的文件覆盖仓库根目录的 `nav.json`
6. 提交、推送并等待 GitHub Pages 重新发布

### 直接编辑数据文件

`nav.json` 的根结构是一个数组：

```json
[
  {
    "category": "分类名",
    "icon": "<svg ...>...</svg>",
    "links": [
      {
        "title": "网站名",
        "url": "https://example.com/",
        "desc": "可选描述",
        "icon": "https://example.com/favicon.ico"
      }
    ]
  }
]
```

- `icon` 可填写 SVG 字符串、图片 URL 或留空
- `desc` 为空时仍可正常显示
- 若保留 `data.js` 作为离线回退，请同步更新其内容与 `nav.json`

### 重要说明

"保存"与"发布"不是同一动作。本地保存通常写入浏览器草稿；只有将导出的
`nav.json` 提交到仓库，其他访问者刷新后才会看到更新。

## 主题与系统跟随

- 默认主题由 `prefers-color-scheme: dark` 决定
- 切换系统外观后，页面会实时跟随
- 点击底部主题按钮可临时切换当前会话
- 刷新页面后会重新读取系统偏好
- 当前不把手动选择写入持久化存储

深色主题由 `html[data-theme="dark"]` 与 CSS 变量控制。修改主题色时优先
调整 `:root` 中的 `--primary` 等变量。

## 搜索与快捷键

- `/`：聚焦搜索框
- `Esc`：在搜索框中取消焦点；在模态框打开时关闭模态框
- `Enter`：提交当前搜索词
- 站内搜索：匹配标题、网址与描述
- 外部搜索：选择 Bing、百度或 Google 后提交，将在新标签页打开结果页

后台也包含搜索框，但主要用途是编辑数据；使用前请确认实际版本中编辑控件
与搜索结果的交互。

## 自定义与二次开发

### 更换站点标题

修改 `index.html` 与 `admin.html` 的 `<title>` 及 `.logo` 文本。

### 修改颜色或圆角

编辑 `styles.css` 中的 `:root` 变量，不建议直接修改所有卡片样式。

### 修改数据结构

新增字段时，应同时检查：

1. `nav.json`
2. `data.js`
3. 卡片渲染模板
4. 后台编辑弹窗
5. 搜索过滤逻辑

### 增强后台安全

当前后台没有身份验证。公开部署时建议：

- 将仓库或 Pages 设为私有
- 使用反向代理增加访问控制
- 将 `admin.html` 排除在公开站点之外
- 或改为后端 API/提交接口，避免浏览器直接编辑数据

## 部署到 GitHub Pages

1. 将仓库推送到 GitHub 默认分支
2. 打开仓库 Settings → Pages
3. Source 选择默认分支，目录选择 `/ (root)`
4. 保存后等待站点构建
5. 访问 `https://<用户名>.github.io/nav`

本项目没有构建步骤，也不要求 Node.js 依赖。仓库中未发现已启用的自动构建
或自动同步工作流，发布 `nav.json` 需要提交文件并等待 Pages 更新。

## 常见问题

### 打开后看不到 nav.json 的内容？

请使用 HTTP 服务，而不是双击文件。直接打开时 `fetch('nav.json')` 可能因
`file://` 协议失败，页面会回退 `data.js`。

### 修改了后台但没有生效？

后台本地保存通常只更新浏览器草稿。请导出 `nav.json`，覆盖仓库文件并提交
发布。

### 修改 nav.json 后访问者仍看到旧数据？

等待 Pages 完成发布，并清除浏览器缓存；页面已使用时间戳与 `no-store`
降低缓存影响，但仍可能因 CDN 有短暂延迟。

### 主题没有固定？

当前采用系统跟随优先。若需要固定主题，可扩展 localStorage 持久化逻辑。
